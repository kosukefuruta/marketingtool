# 施策選択ロジック（案）

最終更新: 2026-09-27
関連資料: [施策型カタログ](action-type-catalog.md)、[目標駆動型SEO施策エンジン構想](goal-driven-action-planning.md)

## 1. この文書の位置づけ

[施策型カタログ](action-type-catalog.md)は「どんな施策型が存在するか」を定義する。本書は「差分からどの施策型を引くか」を定義する。構想文書§8（施策候補の生成）と§12（施策セット）の具体化にあたる。

目標の差分を出せるようになった段階で、差分と施策の間に必要な層が2つあることが分かった。

1. **目指す状態の選択**: 同じ差分でも、どのドライバーで埋めるかによって施策が入れ替わる
2. **足りているかの判定**: どのドライバーも同じように高められるとは限らない

## 2. 全体の流れ

```text
① 目標と現状の差分を出す                     （実装済み）
② 目指す状態を選ぶ（慎重・標準・好調）        （実装済み）
③ 選んだ状態での、ドライバーごとの必要値と差分  （実装済み）
④ 各ドライバーが「足りていない」かを判定する    （未実装）
⑤ 差分のあるドライバーに紐づく施策型を引く      （未実装）
⑥ 適用条件をデータで評価し、施策インスタンスを生成（未実装）
⑦ 優先順位を付けて提示する                    （未実装）
```

## 3. 目指す状態は達成シナリオで選ぶ

同じ差分でも、率を上げて埋めるか、流入を増やして埋めるかで施策はまったく変わる。この選択は、既にある達成シナリオ（慎重・標準・好調）と同じものである。シナリオは率の前提を3点で持っているため、そのままレバーの選択肢として使える。

CV月10件が目標の場合。

| シナリオ | CTA到達率 | CTA CVR | 必要な自然検索 | 意味 |
|---|---|---|---|---|
| 慎重 | 2% | 0.5% | 100,000 | 率は下振れのまま。流入で埋める |
| 標準 | 3% | 1% | 33,334 | 率は現在の推定水準で推移する |
| 好調 | 5% | 2% | 10,000 | 率を上振れまで改善する。流入増は不要になりうる |

必要流入に10倍の開きがある。好調を選べば記事を1本も書かずに達成できる可能性がある代わりに、率を上げる施策（CTA追加、フォーム改善）が必要になる。慎重を選べば率はそのままでよい代わりに、流入施策（記事作成、順位改善）が大量に必要になる。

**シナリオの選択 = 施策の選択**である。

## 4. 率と量では判定方法が違う

| 種別 | 例 | 基準の有無 | 判定方法 |
|---|---|---|---|
| 率 | CTA到達率、CVR、無料→有料転換率、ページRPM | ある（事前分布・ジャンル別） | 基準帯と比較して「足りているか」を判定できる |
| 量 | 表示回数、セッション、PV | ない | 目標からの逆算でしか必要量が決まらない |

自然検索セッション数に「一般的な正しい値」は存在しない。サイト規模でもテーマでも変わる。したがって量は単独で「足りているか」を判定できず、**率で埋めきれなかった残りを引き受ける形でしか必要量が決まらない**。

## 5. 率が足りているかの判定

実測はベイズ補正済みの中央値と70%信用区間、基準はジャンル別の慎重・標準・好調の3点。両者を比較する。

| 実測の位置 | 判定 | 扱い |
|---|---|---|
| 信用区間の上端 < 標準 | 足りていない | レバー候補。伸び代は好調値まで |
| 区間が標準をまたぐ | 平均的 | レバーにはなるが伸び代は小さい |
| 信用区間の下端 > 好調 | 既に強い | レバーにしない。伸ばすのは非効率 |
| 区間が広く判別できない | 判断できない | 計測量が不足。まず観測を増やす |

最後の行を必ず用意する。CTA到達20セッション中1件でCVR 5%でも、それは「高い」ではなく「分からない」である。構想§8.3の「単一シグナルで施策を断定しない」はここで効く。

### 5.1 判定できるドライバーの現状

| ドライバー | 基準 | 判定 |
|---|---|---|
| CTA到達率、CTA CVR、無料CVR、無料→有料転換率 | ジャンル非依存の事前分布 | 可能 |
| ページRPM | ジャンル別の事前分布 | 可能 |
| セッションあたりPV | なし | 不可。基準を決める必要がある |
| 検索CTR | 順位別の期待CTRが必要 | 不可。期待CTR表が未定 |
| 平均掲載順位 | 相対評価 | 不可 |
| 表示回数、セッション、PV | 量 | 逆算のみ |

検索CTRを判定できないことの影響が大きい。CTRは順位でほぼ決まるため、順位を揃えずに「低い」とは言えない。順位別の期待CTR表が無い限り、SERP-001（title改善）とSERP-002（description改善）の適用条件を評価できない。

## 6. 率の差分をどう出すか

率の必要値をそのまま差分にすると、実際には求めていない改善を要求してしまう。実測の生値は観測量が少ないほど揺れるためである。

そこで、率の差分は**実測の生値ではなく推定中央値（標準シナリオの前提）との差**で出す。

| シナリオ | 率の必要値 | 差分 |
|---|---|---|
| 慎重 | 下振れ値 | 達成（現状維持でよい） |
| 標準 | 推定中央値 | 必ず達成。逆算に使った率と二重に手を打つことを防ぐ |
| 好調 | 上振れ値 | 「あと◯ポイント」。利用者が選んだ目標なので正当な差分 |

量（セッション、PV、表示回数）は実測があるときだけ差分を出す。仮定値との差は差分ではない。

## 7. ドライバーから施策型を引く

④で差分が確定したドライバーに対し、カタログから施策型を引く。

| ドライバー | 施策型 |
|---|---|
| impressions（検索表示回数） | CRAWL-001〜004, INDEX-001〜004, INTENT-001〜003, INTENT-005, RANK-001〜004, DUP-001, DUP-002, LINK-002, LINK-003, AUTH-001〜003 |
| ctr（検索CTR） | SERP-001〜004, INTENT-003, INTENT-004, RANK-001, UX-001, UX-002 |
| cta-rate, cta-sessions（CTA到達） | CV-001, CV-002, LINK-001, UX-003 |
| cta-cvr, free-cvr（CV率） | CV-003, CV-004, CV-005, UX-003 |
| paid-rate（無料→有料） | CV-006, CV-007 |
| pageviews, pages-per-session（回遊） | FLOW-001, FLOW-002 |
| page-rpm | CV-008, CV-009 |
| 全ドライバー（監視） | MON-001〜003 |

同じ施策型が複数のドライバーに現れる。構想§8.4のとおり、重複と粒度の整理が必要になる。

## 8. 実装状況

| 段階 | 状態 |
|---|---|
| ① 目標との差分 | 実装済み。不足量・達成率・進捗バー |
| ② 目指す状態の選択 | 実装済み。目標詳細でシナリオを切り替える |
| ③ ドライバーごとの必要値と差分 | 実装済み。シナリオに応じて必要値が変わる |
| ④ 足りているかの判定 | 未実装。材料（実測・信用区間・基準帯）は揃っている |
| ⑤ 施策型の引き当て | 未実装 |
| ⑥ 施策インスタンスの生成 | 未実装。追加データなしで8施策型は生成できる |
| ⑦ 優先順位 | 未実装。合成方法が未決 |

## 9. 未決事項

| 項目 | 内容 |
|---|---|
| 優先順位の合成 | 差分の大きさ、工数、成功確率をどう合成するか |
| シナリオの現実性 | 好調を選べても、そのサイトで率が上がるとは限らない。§5の判定でレバーを絞る必要がある |
| 効果の見積り | 各施策型がドライバーをどれだけ動かすか。構想§19に初期値未定 |
| 期待CTR表 | 順位別CTRの初期値。SERP群の適用条件に必須 |
| セッションあたりPVの基準 | 判定に必要 |
| 施策セットとフェーズ | 構想§12・§13。単独施策ではなく依存関係を含むまとまりで計画する |
| 実行者の条件 | 記事作成のような工数の大きい施策を、利用者の使える時間に応じてどう出し分けるか |
