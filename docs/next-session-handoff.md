## 次にやること

到達可能性には、狙うキーワードとそのボリュームが要る。Search Consoleで表示されたクエリは、偶然拾っているものを含み、狙うキーワードとは別物である。またキーワードは利用者に入力させるのではなく、こちらから提示する。

1. 対象キーワードの提案（種＝既存ページの内容とGSCクエリ → DataForSEO Labsで候補拡張 → ボリューム付与 → クラスタで提示）
2. ④到達可能性（対象キーワード群の需要合計と必要量を比較する。不足分がそのまま「増やすべきキーワードの量」になる）
3. ⑤ボトルネックの特定（率は基準帯と信用区間の比較）。追加データ不要
4. ⑥フェーズと中間目標（状態で区切り、期限は持たない）
5. 診断ベースの8施策型（CRAWL-001〜003、INDEX-001〜004、DUP-001）。追加データ不要
6. 内部リンク構造の保存（5施策型を解放）

到達可能性で「届かない」と出ることは悪い知らせではなく、狙うキーワードを増やす合図である。

## 本番で見つけた不具合と対処（2026-09-27）

テストでは見つからず、実データで分かったもの。同じ種類の見落としに注意する。

- 検索需要の表が一度も表示されていなかった。Suspenseの差し替えが本番で完了せず、フォールバックのまま固定されていた。キャッシュが効くと即座に解決してフォールバックが出ないため、遅いときだけ壊れていた（PR #49で解消）
- 自然検索6セッション中6件の観測で、CTA到達率の前提が3%から11.25%へ動き、必要流入が4分の1に見えていた。観測量で補正の強さを決めるようにした（PR #47）
- DataForSEOのキャッシュが、APIが返した綴りで書き、要求した綴りで読んでいたため当たらず、ページを開くたびに課金されていた（PR #45）
- Google Adsのキーワード制約は1件でも違反するとタスク全体が失敗する。送信前に除外する（PR #48）

## 対象国・言語の扱い（未対応）

検索ボリュームの取得は全サイトで日本固定（`location_code: 2392`、`language_code: "ja"`）である。英語圏向けサイトでは実態と合わない値が返る。サイトごとに対象国・言語を持たせる必要があり、スキーマ変更を伴う。

並行して残っている運用課題は次のとおり。

- Stripe本番モードの設定と契約開始確認
- `docs/paid-feature-requirements.md`の施策管理・効果測定（施策の状態、実施日、修正前後、メモ、実施前後比較）の実装

DataForSEOの導入は、外部SEOデータAPIとして計画済みだが着手はPhase 2完了後とする。契約前にデータ保存可否の確認が必要である。
